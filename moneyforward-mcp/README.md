# moneyforward-mcp

Money Forward ME の入出金を読み、二重に数えられている取引を探して直すための、ローカルの MCP サーバです。取引のカテゴリの変更、予算の実績と設定の読み書き、連携している口座の残高と更新状態の読み取りもできます。MF ME には公式の API がないので、ログイン済みの Chrome を Playwright で操作します。

## 準備

```bash
cd moneyforward-mcp
npm install
npm run login
```

`npm run login` で開いた Chrome に、ご自身でログインします（Google でのログインも使えます）。入出金のページが表示されたら、その Chrome を ⌘Q で終了してください。終了すると、ログインできたかを自動で確かめます。いつもの Chrome とは別に起動するので、⌘Q はログイン用の方に押してください。

ログインの状態は `~/.moneyforward-mcp/chrome-profile` に残り、MCP サーバはこのプロファイルを使います。パスワードはこのリポジトリのコードを通りません。Playwright から開いた Chrome では Google ログインが拒否されるので、ログインのときだけは普通の Chrome を起動しています。

Claude Code に登録します。

```bash
claude mcp add moneyforward -- node /path/to/userscripts/moneyforward-mcp/server.js
```

## ツール

| ツール | すること |
| --- | --- |
| `list_transactions` | 指定した月の範囲（最大 24 か月）の入出金を読む |
| `find_duplicates` | 二重に数えられている取引を探す。何も変えない |
| `set_calc_target` | 取引を計算対象外（または計算対象）にする |
| `set_category` | 取引の大項目と中項目を変える |
| `set_transfer` | 取引を振替にし、相手側の入出金を振替先に結びつける |
| `get_budget` | 指定した月（省くと今月）の予算の実績と、毎月の予算の設定を読む |
| `set_budget` | 毎月の手取り収入と、大項目ごとの予算を変える |
| `get_accounts` | 連携している口座の残高・最終取得日・更新状態を読む |

`set_calc_target`・`set_category`・`set_transfer`・`set_budget` は、ページを読み込み直して保存された値を確かめてから、結果を返します。どれも MF の画面から元に戻せます。取引を削除するツールはありません。変更した内容は `~/.moneyforward-mcp/audit.log` に 1 行ずつ記録します。送る前に `"result":"started"` の行を書き、終わったら結果の行を書きます。`started` の行だけが残っていたら、その操作は途中で止まっています。

## カテゴリ

`set_category` には、大項目と中項目の名前を渡します。名前は `list_transactions` の `large`・`middle` と同じものです。ない名前を渡すと、何も変えずに、指定できる名前をエラーで返します。収入と支出では選べるカテゴリが違います。振替の取引にはカテゴリがないので、結果は `not_found` になります。結果には変更前のカテゴリ（`before`）が入り、`audit.log` にも残るので、同じツールで元に戻せます。

## 口座

`get_accounts` は、MF の「登録済み金融機関」のページを読みます。カードのように残高の出ない口座は、`balance` が `null` になります。`status` が「正常」でない口座は更新が止まっていて、`lastFetched` より後の取引は入出金に入っていません。

## 予算

`get_budget` は、MF の「今月の予算」と「予算の設定」の 2 つのページを読みます。

- `progress`: その月の予算・使った金額・残り。支出全体、変動費と固定費の小計、大項目の順に並びます。画面には使った金額と残りしか出ないので、予算は 2 つを足して求めています
- `settings`: 毎月の手取り収入と、大項目ごとの予算・先月の実績

`set_budget` には、大項目の名前と新しい額を渡します。指定しなかった大項目は変わりません。名前が 1 つでも設定画面にないと、何も変えずにエラーを返します。結果には変更前の額（`before`）が入り、`audit.log` にも残るので、同じツールで元の額に戻せます。

MF の予算は月ごとには持てず、全部の月に共通です。予算を変えると、過去の月の「残り」も変わります。大項目を変動費と固定費に振り分ける「大項目の設定」は、このサーバでは変えられません。

## 重複とみなす条件

- **自分名義の振込**（`own_transfer`）: 銀行口座からの「振込」の出金と、別の銀行口座への入金が、同じ名義・同じ額で、3 日以内にある。振替にする
- **二重の連携**（`duplicate_link`）: 2 つの連携（例: モバイル Suica を 2 つの ID で連携）の期間が重なり、その中でどちらの取引も 98% 以上が日付・金額・内容まで一致する（3 件以上）。更新が先に止まった方の、一致した取引だけを計算対象外にする
- **通販とカード**（`shop_card`）: Amazon・Yahoo!ショッピングの購入履歴の数件（品物・送料・ポイント・クーポン）の合計が、その 1 日前から 10 日後までのカード明細の 1 件と一致する。カード側を計算対象外にする

計算対象外の取引は判定に使わないので、直したあとに同じ期間をもう一度調べても、同じ操作は提案されません。

判定は金額の一致に頼っているので、誤って本物の支出を候補に挙げることがあります。とくに「通販とカード」は、購入履歴に出ない請求（Prime・Kindle などの定期の支払い）が、近い日付の品物とたまたま同じ額だと一致してしまいます。直す前に、`find_duplicates` の一覧（`detail` に何と何が一致したかが出ます）を必ず見て、了承したものだけを直してください。

`set_transfer` は、同じ額の出金と入金の組み合わせしか受け付けません。

## 注意

- MF はヘッドレスの Chrome を拒否する（403）ので、最初にツールを使ったときに画面ありの Chrome を起動し、ウィンドウをすぐに最小化します。起動した瞬間は Chrome が前面に出ます。Chrome はツールを使い終わっても閉じず、MCP サーバが終わるまで Dock に残ります。User-Agent を偽ってこの制限を避けることはしていません
- MCP サーバと `npm run login` は同じプロファイルを使うので、同時には動かせません
- 画面のクラス名やフォームに依存しているので、MF の画面が変わると動かなくなります
- MF の「月の開始日」は 1 日の設定を前提にしています。ほかの日にしていると、月を移るところで止まります（データは変えません）
- 自動での操作が MF の利用規約に触れないかは、利用者自身で確かめてください

## テスト

```bash
npm test
```

重複の判定、カテゴリの名前の照合、口座と予算の値の読み取り、予算の変更内容の検証（`lib.js`）だけをテストします。MF の画面を操作する部分（`mf.js`）は、実際のアカウントで動かして確かめています。
